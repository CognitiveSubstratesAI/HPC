# HPC — Audit (2026-06-05)

Method: deep read of all 8 src modules + 5 test files (subagent first pass),
then **every finding verified against the code by hand** before recording. No
external audit doc existed; this is read + spec-diff + a targeted `Base.hash`
determinism check. Severities below are my corrected severities — two subagent
findings were over-rated and are explicitly marked REFUTED/DOWNGRADED.

HEAD audited: `67f145f`. Package = MORK + MPI distributed multi-space sharding,
1191 LOC. Single-node (`mpi_active()==false`) paths are clean and tested; the
**distributed MPI layer is structurally unsound and has zero CI coverage** —
that is the headline.

## ⚠️ Meta-finding (drives everything): the MPI layer is untested
`test/runtests.jl` includes only `test_multispace.jl`, `test_mpi_transport.jl`,
`test_sharded_space.jl` — all of which run with `mpi_active()==false` and
short-circuit before any MPI call. **`integration_test.jl` (the only multi-rank
harness, run via `mpiexec`) is ORPHANED — never included by `Pkg.test`.** So
every HIGH finding below lives exclusively in code `Pkg.test` never executes.
The commit message claims "integration test passing on 4 ranks", but that is a
manual `mpiexec` run, not gated. **Top recommendation: wire a real
`mpiexec -n 2` run into CI before trusting any distributed result.**

## HIGH (real, verified)

| ID | Where | Finding |
|----|-------|---------|
| **HPC-1** | ShardedSpace.jl:107-109 | `sharded_add!` does `atom_bytes = Vector{UInt8}(atom_str); MPI.Isend(atom_bytes, …)` — the returned `Request` is discarded AND `atom_bytes` goes out of scope when the function returns. Classic MPI non-blocking send buffer-lifetime bug: MPI may still be reading the buffer after GC reclaims it. Masked for small **eager**-protocol messages (MPI copies immediately); corrupts/loses data for large **rendezvous** messages. |
| **HPC-2** | ShardedSpace.jl:108, MPITransport.jl:104, :137 | Same discarded-`Request` pattern in 3 sites; there is **no `Wait`/`Waitall`/`Test` anywhere** in the package (verified by grep). Requests are never completed or freed. The integration test's `mpi_barrier!` "wait for sends" comment is wrong — a barrier does not complete outstanding `Isend`s. |
| **HPC-3** | ShardedSpace.jl:96-134 | Shard write protocol has **no delivery guarantee**: senders fire-and-forget `Isend`; owners drain via `Iprobe`+`Recv!` in `sharded_flush!`. `Iprobe` only sees already-arrived messages, and with no sender-side `Wait` there is no point at which an atom is guaranteed delivered. `integration_test.jl` calls `barrier`+`flush` **twice** "for late arrivals" — an admission the protocol is racy. Atoms can be silently lost. |

## MED (real, verified)

| ID | Where | Finding |
|----|-------|---------|
| **HPC-5** | MultiSpace.jl:171-184 + ShardedSpace.jl `sharded_query`/`sharded_val_count` | Collective-symmetry contract is unenforced. `new_space!` creates a `ShardedSpace` only when `role==:common && mpi_active()`, else a plain `Space`. If ranks register different names/roles, their registries diverge and a collective (`Bcast`/`Allgatherv`/`Allreduce`) called on some ranks but not others **deadlocks the whole job**. No guard, no doc of the SPMD requirement. |
| **HPC-7** | MultiSpace.jl:219-228 | `list_spaces` iterates only `keys(reg.spaces)` — it **omits `reg.sharded_spaces` entirely**, so under MPI the `:common` (sharded) spaces silently vanish from the listing while `get_space`/`common_space` still return them. Inconsistent registry view. (Proper fix needs the `Allreduce` count, so it is not a trivial one-liner.) |
| **HPC-11** | ShardedSpace.jl:159 | `sharded_query` hardcodes `mpi_bcast_bytes!(pat_bytes, LOCAL_PEER)` (root=rank 0) despite the docstring saying "any rank may initiate". A non-zero initiator's pattern is discarded; rank 0's (possibly empty) pattern is what gets broadcast. Only correct if every rank passes the identical pattern. |
| **HPC-13** | MPITransport.jl:62-67 | `mpi_finalize!` is never registered via `atexit`, though `mpi_init!` is auto-called from `enable_multi_space!`. A program that enables MPI and exits without manually finalizing risks an `MPI_Finalize`-not-called abort. |

## LOW (verified) / corrected

| ID | Where | Finding |
|----|-------|---------|
| **HPC-6** | ShardedSpace.jl:75 | **REFUTED as HIGH → LOW.** Subagent claimed `hash(atom_bytes)` is "not stable across processes → data corruption". **Verified false:** two separate Julia processes produce the identical `hash(Vector{UInt8}("(edge a b)"))` = `13379191715385688234`. Julia does **not** randomize `hash` per-process (unlike Python); it is deterministic for a given build. Real residual risk is only **cross-Julia-version heterogeneity** (different builds per rank) — pathological, and not "silent corruption" on a normal homogeneous cluster. Worth a fixed FNV/CRC only if heterogeneous builds are ever a target; otherwise leave. |
| **HPC-4** | MPITransport.jl:212-220 | **DOWNGRADED.** Subagent itself walked back the desync claim (`Allgatherv` displs keep the loop aligned). Residual real points are minor/defensive: no bounds-check on `read(io, slen)` (a garbled `recv_buf`, e.g. from HPC-1, throws `EOFError` inside a collective → all ranks crash), and host-endianness length prefixes (heterogeneous-endian only). LOW. |
| **HPC-12** | ShardedSpace.jl:107 vs :79, MPITransport.jl:193 | **DOWNGRADED to cosmetic.** `Vector{UInt8}(::String)` vs `collect(codeunits(::String))` produce **identical** UTF-8 bytes; the routing-key vs payload paths agree today. Consistency nit, not a bug. |
| **HPC-14** | MultiSpace.jl:239-243 | `compute_cid` is a `hash(n)` stub (atom-count only → collisions); `NamedSpaceID.cid` is otherwise unused. Dead-ish. Marked "Stage 1 stub". |
| **HPC-15** | MPITransport.jl:27,247 | `RESULT_TAG` declared + exported but never used. Dead constant. |
| **HPC-17** | MM2Commands.jl:117-122 | `_extract_string` accepts a list arg by returning its serialized s-expr — `(new-space (foo bar) common)` silently names the space `"(foo bar)"` instead of erroring. Loose validation. |

## Reproducibility finding (independent of the agent pass)

**HPC-PKG-1 (MED):** `Project.toml` has **no `[sources]` section** at all, yet HPC
depends on the unregistered `MORK`. Resolution works only because the gitignored
`Manifest.toml` carries `MORK = {path="../MORK"}`. A clean CI checkout / fresh
clone cannot resolve `MORK` and fails to instantiate. Fix: add
`[sources]\nMORK = {path = "../MORK"}` (mirroring MORKTensorNetworks). PathMap is
transitive via MORK and also needs listing if instantiate complains. Low-risk,
verifiable by a clean-env resolve.

## Bottom line
The local/registry/parser/persistence layers are solid and tested. The
distributed layer — the package's entire purpose — needs: (1) retain `Isend`
buffers+requests and `Waitall` them (or switch the shard exchange to a
synchronizing `Alltoallv`), (2) a real delivery/ack so no atom is lost, (3) a
gated `mpiexec -n 2` test before any of this can be trusted. None of these
should be fixed blind — they require multi-rank validation, so they are
documented here rather than patched in this pass. HPC-6 and HPC-12 are NOT bugs
(corrected); do not "fix" them speculatively.
